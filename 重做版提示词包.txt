============================================================
智慧客房 · 重做版提示词包（OpenCode）
============================================================

用途：
- 这是“重做一遍”的提示词模板，不是本次提交的 PROMPTS 文件。
- 不要把这个文件放进 提交/PROMPTS/，否则会混入非比赛提示词。
- 建议按顺序复制发送，每次只发一个提示词，等这一步通过再发下一步。

使用原则：
1. 先建立 PROJECT_SPEC.md，后续提示词只写“先读 PROJECT_SPEC.md”。
2. 一次只做一个 Feature，完成就 build，不要最后一次性修。
3. 每个提示词都写清楚“只允许改哪些文件”，防止 AI 顺手重构。
4. 每个阶段都必须运行测试/构建，失败先修，不要只说“已完成”。
5. 不伪造签名、不声称模拟器已安装、不把未执行的 UI 用例写成通过。
6. 文档和图片最后生成，以实际代码为准，不要凭记忆写。

建议时间分配（240 分钟）：
- 10 分钟：生成 PROJECT_SPEC.md
- 30 分钟：工程骨架 + Commons + phone 壳
- 90 分钟：5 个 Feature（每个约 18 分钟）
- 30 分钟：集成、轮询、Token、错误处理
- 30 分钟：测试 + 修复
- 25 分钟：ModuleA 文档、draw.io、PNG
- 25 分钟：打包、HAP、报告、提示词导出、检查


============================================================
提示词 01：生成项目事实卡 PROJECT_SPEC.md
============================================================

【提示词开始】

读取当前工作区的接口文档、UI 素材包、运行效果视频和已有工程。
生成 PROJECT_SPEC.md，只写事实，不要写业务代码，不要提问。

必须包含：

1. 架构与目录
- Commons / Features / Products 三层完整目录树
- 每个 HAR 的包名、职责、入口文件
- products/phone 的 HAP 配置、入口 Ability、页面路由

2. 状态与数据
- AppState 全部字段、类型、默认值
- AppState 的写回方法、重置方法
- token 的存储方式与读取方式
- 3 秒轮询的启动/停止位置

3. API 表
逐项列出：方法、路径、鉴权、请求体、响应体、错误码
必须覆盖：
- 登录 / 登出
- 整房快照
- 空调开关、温度
- 灯光总开关、场景、单灯
- 窗帘单帘、批量
- 客房服务开关、SOS

4. 页面与交互
5 个页面：登录、首页、灯光、窗帘、客房服务
每个页面写：入口、路由名、核心组件、空态/加载态、失败提示

5. UI token
从素材包提取：主色、背景色、卡片色、文字色、危险色、
字号层级、圆角、间距、阴影、背景图使用方式
logo 素材缺失时使用占位并记录，不要自行生成品牌 logo

6. 测试矩阵
登录场景、设备控制场景、异常处理场景
每条写：输入、预期、对应接口、测试文件建议

7. 验收命令
- ohpm install --all
- hvigorw test --mode module -p module=phone@default -p product=default --no-daemon
- hvigorw assembleHap --mode module -p product=default --no-daemon

8. 禁止事项
- 禁止 @State/@Prop/@Link 等 V1 装饰器
- 禁止 router，统一 Navigation + NavPathStack
- 禁止 View 直接调用 ApiService/HttpClient
- 禁止 ViewModel 直接操作 UI 组件
- 禁止修改赛场 Mock 后端源码
- 禁止改动素材包原始文件
- 禁止把未执行用例写成通过

完成后只输出：
- PROJECT_SPEC.md 的章节目录
- 关键风险 3 条
- 需要我确认的素材缺口（如有）

【提示词结束】

提示词 02：工程骨架与 Commons
============================================================

【提示词开始】

先读 PROJECT_SPEC.md，按其中目录树搭建工程骨架。
只实现骨架和公共能力，不要实现 5 个业务页面。

必须完成：

1. 根工程
- build-profile.json5 注册 commons 4 个模块、features 5 个模块、products/phone
- 根 oh-package.json5 配置 hypium/hamock
- 每个 HAR 的 module.json5 类型为 har
- products/phone 的 module.json5 类型为 entry

2. Commons 4 个 HAR
- @smart_hotel/utils：BusinessRules、Scale、Theme
- @smart_hotel/network：HttpClient、ApiService、AuthToken、Constants、Models
- @smart_hotel/datastore：AppState、RoomRepository、TokenStore
- @smart_hotel/uicomponents：Backdrop、ToggleSwitch、PageTitle、TabBar

3. phone 产品壳
- PhoneApp：登录态切换、Navigation、NavPathStack、4 个 Tab
- pages/Index：@Entry，只挂载 PhoneApp
- EntryAbility：沉浸式、安全区、TokenStore 初始化
- 轮询生命周期：页面可见时启动，退出时停止

4. 约束
- 全部使用 ArkUI V2 装饰器
- 跨模块 import 使用 @smart_hotel/* 包名
- 不实现具体业务逻辑，不写假数据页面
- 不改后端、不改素材

验收：
1. ohpm install --all
2. hvigorw assembleHap --mode module -p product=default --no-daemon
3. 失败先修，不要结束
4. 输出：新增文件、构建结果、下一步建议
